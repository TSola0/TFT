TFT 桌面显示挂件 · 开发手册 v1.0

主控：STM32F103C8T6（72MHz / 64KB Flash / 20KB RAM） · 显示：SPI TFT（ST7789 240×240） · 语音：ASRPRO 离线语音识别 · 工具链：STM32CubeMX 6.17 + MDK-ARM V5.32 + HAL

01项目概述

本项目制作一个桌面智能显示挂件：圆形/方形小尺寸 TFT 屏显示时钟、天气、表情等信息，通过 ASRPRO 离线语音模块实现语音唤醒与指令控制（如「切换表情」「现在几点」），整体封装为桌面摆件。

核心功能

  • TFT 显示：时钟表盘 / 像素表情 / 天气卡片多页面轮播
  • 语音交互：唤醒词 + 10 条左右离线指令
  • 语音反馈：ASRPRO 板载喇叭播报应答
  • SPI + DMA 高帧率刷屏（局部刷新 >30fps）
  • 预留 USART2：可接 ESP8266/ESP-01 联网取天气

设计约束

  • RAM 仅 20KB → 禁止全屏帧缓冲，必须用局部窗口刷新
  • Flash 64KB → 图片资源需取模压缩、按需存放
  • 挂件供电：USB 5V 输入，AMS1117-3.3 稳压
  • ASRPRO 为 3.3V 逻辑，与 STM32 直连，无需电平转换

02系统架构

A
ASRPRO 语音识别模块（独立运行）— 麦克风拾音 → 离线识别唤醒词/命令词 → 板载喇叭播报 TTS 应答，同时通过 UART 把「指令码」发给 STM32。
⇩
USART1 @115200，自定义帧协议（见第 7 章）
B
STM32F103C8T6 主控 — 解析指令 → 更新 UI 状态机 → 通过 SPI1 + DMA 驱动 TFT 刷新画面。SysTick 1ms 节拍驱动软定时器，负责时钟走秒、页面轮播、动画帧。
⇩
SPI1（PA5/PA6/PA7）+ GPIO 控制脚（CS/DC/RST/BL）
C
TFT 液晶屏（ST7789V 控制器，1.54″/1.9″ 240×240，SPI 接口）— 显示表情、时钟、天气等内容。
D
（可选扩展）ESP-01S WiFi 挂在 USART2 上，接入心知天气 / 高德 API 获取实时天气。
职责划分要点：ASRPRO 只做「耳朵和嘴」，识别到命令后只发一个指令码；所有显示逻辑、页面状态机都在 STM32 上。这样 ASRPRO 侧逻辑简单，语音固件与 UI 固件可独立迭代喵。

3.4 供电设计

  • 整机峰值电流：TFT 背光约 30–50mA + ASRPRO 识别时 ~50mA + STM32 ~40mA ≈ 150mA 内，USB 供电完全够。
  • 走线建议：电源与信号分开走；背光电流较大，若屏幕偏暗可在 BL 电路加一只 100Ω 限流调整亮度。
  • 调试阶段用 ST-Link 供电 + USB 双路时，确保两路 5V 来源共地。

还需要在 CubeMX 补充的步骤：

  1. System Core → GPIO：新增 PA4、PA8、PB0、PB1 四个 GPIO_Output，User Label 分别填 TFT_CS / TFT_DC / TFT_RST / TFT_BL，输出级别 CS/RST/BL 设 High，DC 设 Low。
  2. SPI1 参数确认：CPOL=Low、CPHA=1 Edge（Mode 0）、First Bit=MSB、Data Size=8bit、NSS 由软件控制（Hardware NSS 保持 Disable）。
  3. （推荐）SPI1 Baud Rate Prescaler 从 4 改为 2。
  4. （可选）背光调光：把 PB1 改为 TIM3_CH4 PWM 输出，做呼吸灯 / 亮度调节。
  5. 重新 Generate Code（勾选 Keep User Code），Keil 中编译确认 0 Error。
帧率估算喵：240×240×16bit 全屏 = 115200 字节。SPI 36Mbps 下理论 ~3.9ms，加命令开销全屏 ~7ms（≈140fps）；局部区域（如 64×64 表情框）只需 8KB，毫无压力实现流畅动画。20KB RAM 放不下全屏帧缓冲，所以所有绘图 API 都直接「写窗口 → 推像素」到屏幕 GRAM。

void LCD_WriteCmd(uint8_t cmd)
{
    LCD_DC_LOW();                       /* DC=0 表示命令 */
    LCD_CS_LOW();
    HAL_SPI_Transmit(&hspi1, &cmd, 1, 100);
    LCD_CS_HIGH();
}

void LCD_WriteData(uint8_t *buf, uint16_t len)
{
    LCD_DC_HIGH();                      /* DC=1 表示数据 */
    LCD_CS_LOW();
    HAL_SPI_Transmit(&hspi1, buf, len, 1000);
    LCD_CS_HIGH();
}

5.2 ST7789 初始化序列

/* ST7789V 上电初始化（240x240） */
void LCD_Init(void)
{
    LCD_BL_OFF();
    LCD_RST_HIGH();  HAL_Delay(10);
    LCD_RST_LOW();   HAL_Delay(10);   /* 硬复位 >10us */
    LCD_RST_HIGH();  HAL_Delay(120);

    LCD_WriteCmd(0x11);               /* Sleep Out        */
    HAL_Delay(120);

    LCD_WriteCmd(0x36);               /* MADCTL 屏幕方向   */
    { uint8_t v = 0x00; LCD_WriteData(&v, 1); }  /* 0x00 竖屏 / 0x60 / 0xC0 / 0xA0 */

    LCD_WriteCmd(0x3A);               /* COLMOD 16bit 色   */
    { uint8_t v = 0x55; LCD_WriteData(&v, 1); }

    LCD_WriteCmd(0xB2);               /* Porch 设置 */
    { uint8_t v[5] = {0x0C,0x0C,0x00,0x33,0x33}; LCD_WriteData(v,5); }

    LCD_WriteCmd(0xB7);               /* Gate 电压 */
    { uint8_t v = 0x35; LCD_WriteData(&v,1); }

    LCD_WriteCmd(0xBB);               /* VCOM 设置 */
    { uint8_t v = 0x19; LCD_WriteData(&v,1); }

    LCD_WriteCmd(0xC2);               /* VDV/VRH */
    { uint8_t v[2] = {0x01,0xC3}; LCD_WriteData(v,2); }

    LCD_WriteCmd(0xC6);               /* 帧率 60Hz */
    { uint8_t v = 0x0F; LCD_WriteData(&v,1); }

    LCD_WriteCmd(0xD0);               /* 功率控制 */
    { uint8_t v[2] = {0xA4,0xA1}; LCD_WriteData(v,2); }

    LCD_WriteCmd(0x21);               /* 反色（ST7789 多数模块需要）*/
    LCD_WriteCmd(0xE0);               /* 正极性 Gamma */
    { uint8_t v[14] = {0xD0,0x04,0x0D,0x11,0x13,0x2B,0x3F,
                          0x54,0x4C,0x18,0x0D,0x0B,0x1F,0x23};
      LCD_WriteData(v,14); }
    LCD_WriteCmd(0xE1);               /* 负极性 Gamma */
    { uint8_t v[14] = {0xD0,0x04,0x0C,0x11,0x13,0x2C,0x3F,
                          0x44,0x51,0x2F,0x1F,0x1F,0x20,0x23};
      LCD_WriteData(v,14); }

    LCD_WriteCmd(0x29);               /* Display ON */
    HAL_Delay(50);
    LCD_BL_ON();
}
花屏/白屏先查这三个喵：① 0x21 反色指令——部分模块不需要，白屏了就去掉；② MADCTL(0x36) 与偏移——个别 1.3″ 屏有 0x02 行偏移，竖屏需要 y+2；③ 3.3V 供电是否稳定（背光闪 = 电源带载不足）。

5.3 基础绘图 API

/* 设置写窗口：之后连续写入的数据只落在这个矩形内（省 RAM 的核心！）*/
void LCD_SetWindow(uint16_t x1, uint16_t y1, uint16_t x2, uint16_t y2)
{
    uint8_t buf[4];
    LCD_WriteCmd(0x2A);               /* CASET 列地址 */
    buf[0]=x1>>8; buf[1]=x1; buf[2]=x2>>8; buf[3]=x2;
    LCD_WriteData(buf, 4);
    LCD_WriteCmd(0x2B);               /* RASET 行地址 */
    buf[0]=y1>>8; buf[1]=y1; buf[2]=y2>>8; buf[3]=y2;
    LCD_WriteData(buf, 4);
    LCD_WriteCmd(0x2C);               /* RAMWR 开始写 GRAM */
}

/* 矩形填充（清屏 / 背景色 / 进度条）—— 用 DMA 发送 */
void LCD_Fill(uint16_t x1, uint16_t y1, uint16_t x2, uint16_t y2, uint16_t color)
{
    uint32_t total = (uint32_t)(x2-x1+1) * (y2-y1+1);
    uint16_t chunk[64];                     /* 128B 小缓冲，分块填 */
    for (int i = 0; i < 64; i++) chunk[i] = color;

    LCD_SetWindow(x1, y1, x2, y2);
    LCD_DC_HIGH(); LCD_CS_LOW();
    while (total) {
        uint16_t n = (total > 64) ? 64 : total;
        HAL_SPI_Transmit_DMA(&hspi1, (uint8_t*)chunk, n*2);
        while (hspi1.State != HAL_SPI_STATE_READY);  /* 等 DMA 完成 */
        total -= n;
    }
    LCD_CS_HIGH();
}

/* 画图片（RGB565 数组，取模软件生成）—— 同样 DMA 直推 */
void LCD_DrawBitmap(uint16_t x, uint16_t y, uint16_t w, uint16_t h, const uint16_t *bmp)
{
    LCD_SetWindow(x, y, x+w-1, y+h-1);
    LCD_DC_HIGH(); LCD_CS_LOW();
    /* 小图一次性发；大图按 512 字节分块（见 5.4 优化版）*/
    HAL_SPI_Transmit(&hspi1, (uint8_t*)bmp, w*h*2, 2000);
    LCD_CS_HIGH();
}

5.4 DMA 刷屏的正确姿势

DMA 传输期间 源缓冲区不能被修改、不能在栈上被回收，且单次传输计数最大 65535。工程实践：

/* 大图分块 DMA 搬运（图片存 Flash，DMA 可直接读 Flash） */
void LCD_DrawBitmapDMA(uint16_t x, uint16_t y,
                       uint16_t w, uint16_t h, const uint16_t *bmp)
{
    uint32_t remain = (uint32_t)w * h * 2;   /* 总字节数 */
    const uint8_t *p = (const uint8_t*)bmp;

    LCD_SetWindow(x, y, x+w-1, y+h-1);
    LCD_DC_HIGH(); LCD_CS_LOW();
    while (remain) {
        uint16_t n = (remain > 32000) ? 32000 : remain;
        HAL_SPI_Transmit_DMA(&hspi1, (uint8_t*)p, n);
        while (HAL_SPI_GetState(&hspi1) != HAL_SPI_STATE_READY);
        p += n;  remain -= n;
    }
    LCD_CS_HIGH();
}
DMA 陷阱（Shiro 踩过的坑喵）：① 图片数组必须加 const，否则会占用本就不富裕的 RAM；② 轮询 hspi1.State 即可，若改用中断回调方式，注意 CS 必须在「传输完成回调」里才拉高，不能在启动后就拉高；③ CubeMX 里 SPI1_TX 的 DMA 已开 MINC，正确✓。

5.5 字符、汉字与表情

  • ASCII 字符（8×16）：直接内置字模数组，用于时间数字、调试信息。想要大号时间可再做 16×32 / 24×48 数字字模。
  • 中文/任意字体：用 PCtoLCD2002 取模：阴码、逐行式、顺向（高位在前）、RGB565 可用「图片取模」模式。挂件文案固定（如「天气」「温度」），每个汉字 16×16 占 512B，几十个字毫无压力。
  • 表情图片：用 Image2Lcd 或 Img2Lcd（在线版）：输出 RGB565、水平扫描、包含图像头部分「不勾选」。240×240 全屏图 = 115KB —— 超过 Flash 一半！表情建议做 128×128（32KB/张）或 96×96（18KB/张），Flash 64KB 里预留 ~40KB 给 2~3 张全屏底图 + 若干小表情。
/* 在 (x,y) 显示一个 16x16 汉字（取模为 RGB565 逐行扫描） */
void LCD_ShowChinese16(uint16_t x, uint16_t y, const uint16_t *hanzi)
{
    LCD_DrawBitmapDMA(x, y, 16, 16, hanzi);
}

6.3 天问Block 端编程要点

天问Block 使用类 C 语法，核心思路：识别到词条 → 串口发送一帧指令 → 播报应答。

/* 天问Block 中 ASRPRO 侧逻辑（示意，实际在图形界面拼接） */
#include "asrlib.h"

void ASR_CODE()
{
    /* 已知唤醒词触发，进入命令窗口期 */
    set_state_enter_wake();

    switch (get_voice_id()) {          /* 获取识别到的词条 ID */
    case 1:  /* "切换表情" */
        uart_send_frame(0x01);            /* 发指令给 STM32 */
        play_speech("好的");
        break;
    case 2:  /* "显示时间" */
        uart_send_frame(0x02);
        break;
    case 4:  /* "开心一点" */
        uart_send_frame(0x04);
        play_speech("好耶，我最开心啦");
        break;
    /* ... 其余词条 */
    }
}
  1. 在天问Block「语音识别」页签里添加上表词条，为每条分配 ID。
  2. 用「串口发送」积木按第 7 章的帧格式发送指令（可直接调用串口写十六进制数组积木）。
  3. TTS 播报用「播放语音 / 提示音」积木，可用官方 TTS 在线合成或导出提示音 wav。
  4. 编译下载：Type-C 连接模块 → 一键下载 → 断电重上电测试唤醒。
调音技巧喵：喇叭与麦克风距离 >5cm，且 TTS 播报期间 ASRPRO 会自动回声消除；如果误唤醒率高，在天问Block 里把唤醒词阈值（识别等级）调高 1~2 档。

07通信协议设计（ASRPRO ⇄ STM32）

双端自定义帧协议，简单可靠，带校验和，方便串口助手调试：

字节位01234…末字节
含义帧头 0xAA帧头 0x55CMDLENDATA…（N 字节）SUM（CMD+LEN+DATA 之和低 8 位）

例：「切换表情」完整帧 = AA 55 01 00 01；「显示时间」= AA 55 02 00 02。

7.1 STM32 接收状态机（DMA + 空闲中断，已具备硬件条件）

当前工程 USART1 的 RX 已配置 DMA 与中断，推荐使用串口空闲中断（IDLE）+ DMA 方案——ASRPRO 的帧是短促突发，IDLE 中断天然分帧，不需要逐字节中断：

/* usart.c —— USER CODE 区添加 */
#define RXBUF_SIZE 64
uint8_t  rx1_buf[RXBUF_SIZE];
volatile uint16_t rx1_len = 0;
volatile uint8_t  rx1_flag = 0;      /* 1=收到一帧 */

void UART1_StartIdleRx(void)
{
    /* 使能 IDLE 中断 + 启动 DMA 接收 */
    __HAL_UART_ENABLE_IT(&huart1, UART_IT_IDLE);
    HAL_UART_Receive_DMA(&huart1, rx1_buf, RXBUF_SIZE);
}

/* stm32f1xx_it.c 的 USART1_IRQHandler 里，USER CODE 区调用 */
void USART1_IDLE_Handler(void)
{
    if (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_IDLE)) {
        __HAL_UART_CLEAR_IDLEFLAG(&huart1);
        HAL_UART_DMAStop(&huart1);
        rx1_len = RXBUF_SIZE - __HAL_DMA_GET_COUNTER(&hdma_usart1_rx);
        rx1_flag = 1;                                /* 交由主循环解析 */
        HAL_UART_Receive_DMA(&huart1, rx1_buf, RXBUF_SIZE);  /* 重启接收 */
    }
}

7.2 帧解析与指令分发

/* 主循环里非阻塞轮询（详见第 8 章架构） */
uint8_t Protocol_Parse(uint8_t *frame, uint16_t len, uint8_t *cmd)
{
    if (len < 5) return 0;
    if (frame[0]!=0xAA || frame[1]!=0x55) return 0;
    uint8_t sum = 0;
    for (uint16_t i = 2; i < len-1; i++) sum += frame[i];
    if (sum != frame[len-1]) return 0;   /* 校验失败，丢弃 */
    *cmd = frame[2];
    return 1;
}

7.3 调试方法

  • 先甩开 ASRPRO 单测 STM32：USB-TTL 接 PA10/PA9，用串口助手以 HEX 模式手发 AA 55 01 00 01，看屏幕是否切表情。
  • 再甩开 STM32 单测 ASRPRO：USB-TTL 接 ASRPRO TX，串口助手 HEX 收，确认识别后帧完整、校验正确。
  • 两头都通了再对接，问题基本只剩「交叉接反」和「没共地」喵。

08应用层架构（裸机软定时器）

不上 RTOS，用 SysTick 1ms 节拍 + 软定时器 + 状态机，20KB RAM 完全够用。建议新建 app_ui.c（页面状态机）与 app_voice.c（指令处理）：

/* app 层主骨架（main.c 的 USER CODE 区） */
typedef enum { PAGE_CLOCK, PAGE_WEATHER, PAGE_EMOJI, PAGE_JOKE } Page_t;
typedef struct {
    uint32_t tick_ms;        /* 软定时器 */
    uint8_t  page;           /* 当前页面 */
    uint8_t  emoji_idx;      /* 当前表情 */
    uint8_t  need_refresh;   /* 脏标记，避免无谓刷屏 */
} App_t;
App_t g_app = {0};

/* SysTick 回调：HAL_SYSTICK_Callback()（weak 函数，重写即可）*/
void HAL_SYSTICK_Callback(void) { g_app.tick_ms++; }

/* main() 的 USER CODE 2 区： */
LCD_Init();  LCD_Fill(0,0,239,239, BLACK);
UART1_StartIdleRx();
UI_ShowPage(PAGE_CLOCK);

/* while(1) 区（全部非阻塞）： */
while (1)
{
    /* 1. 处理语音指令帧 */
    if (rx1_flag) {
        rx1_flag = 0;
        uint8_t cmd;
        if (Protocol_Parse(rx1_buf, rx1_len, &cmd))
            Voice_HandleCmd(cmd);            /* 改页面/表情 + 置脏标记 */
    }
    /* 2. 秒级任务：时钟走秒 */
    static uint32_t t_last;
    if (g_app.tick_ms - t_last >= 1000) { t_last += 1000; UI_Tick_1s(); g_app.need_refresh = 1; }
    /* 3. 帧级任务：表情动画 100ms 一帧 */
    static uint32_t t_anim;
    if (g_app.tick_ms - t_anim >= 100) { t_anim += 100; UI_AnimStep(); }
    /* 4. 统一刷新（只刷脏区域）*/
    if (g_app.need_refresh) { g_app.need_refresh = 0; UI_Render(); }
}
时间从哪来喵？F103 有 VBAT 备份域 RTC：接一颗 CR1220 纽扣电池到 VBAT 引脚，CubeMX 开启 RTC（LSE 32.768kHz），断电重启时间不丢。若不接电池，每次上电用 USART2 调试口发指令校时，或日后由 WiFi 模块 NTP 对时。

11常见问题 FAQ

症状原因排查
屏幕全白① RST 接线松；② 初始化序列没发全（尤其 0x11 后要 delay 120ms）；③ 模块不需要 0x21 反色，试着去掉
屏幕花屏/错位① SPI 模式不是 Mode 0；② MADCTL 与屏幕行列起点偏移（试 y+2）；③ DMA 缓冲被修改
颜色反了（蓝脸）RGB/BGR 顺序反了：在 0x36 MADCTL 中翻转 BIT3（0x00 ↔ 0x08）
刷屏卡顿① SPI 还是 Prescaler 4（18Mbps），改 2；② 用了阻塞 HAL_SPI_Transmit 而没走 DMA；③ 每次都全屏重刷，改局部脏区域
串口收到乱码① 波特率不一致；② TX/RX 没交叉；③ 没共地；④ DMA 接收缓冲溢出（检查 IDLE 处理是否重启了接收）
ASRPRO 不识别① 唤醒词阈值太严；② 喇叭离麦克风太近自激；③ 供电不足（5V 输入更稳）
HardFault 死机① 把大数组放栈上（栈仅 0x400，图片请放 const/Flash）；② DMA 源指针指向已释放的栈地址
下载不进程序SWD 线序、BOOT0 跳线（下载保持 BOOT0=0 用 SWD，串口 ISP 才要 =1）
